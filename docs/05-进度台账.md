## 卡点记录

| 日期 | 问题 | 解决方式 |
|---|---|---|
| 10-28 | GitHub 上看不到仓库 —— 只做了 commit，没 add remote 也没 push | ✅ 已解决：改分支名 `main` + 配 remote + push，已核对 `origin/main` = f0063b3 |
| 10-29 | 本地 `git ls-remote` 报 `CRYPT_E_NO_REVOCATION_CHECK`（schannel 证书吊销检查失败） | 是本地网络/证书吊销检查问题，不是仓库问题。push 若再报同错：`git config http.schannelCheckRevoke false` 临时关掉 |
| 11-04 | `vercel dev` 一直返回 `{"error":"missing_api_key"}`，但 Key 确实写在 `.env.local` 里 | ✅ 已解决：这版 CLI（65.11.0）在**已 link 项目**时只读 `.env`，不读 `.env.local`。把变量放到项目根的 `.env` 并重启进程即通。**改 Key 只改 `.env` 一个地方** |
| 11-04 | 打开 `localhost:3000` 白屏，`#app.innerHTML.length` 为 0，控制台没有明显业务报错 | ✅ 已解决：`vercel.json` 的 rewrite `/((?!api/).*)` 把 `/src/main.ts`、`/@vite/client` 也重写成了 `index.html`，返回 `content-type: text/html`，浏览器拒绝执行模块。改成 `/((?!api/\|@)(?!.*\.).*)`——排除 api、`@` 开头的 Vite 内部路径、以及带后缀的真实文件。**排查手法：`curl -s -D - -o /dev/null <模块地址>` 看 content-type，不必翻浏览器** |
| 11-04 | `Ctrl+C` 后以为重启了，其实旧进程还占着 3000，新进程偷偷跑到 3001 | ✅ 已解决：`vercel dev` 会套一层 vite 子进程，Windows 上 Ctrl+C 常只杀外层。判断方式 `netstat -ano \| grep ":3000"`，清理用 `taskkill /PID 号码 /T /F`（`/T` 连子进程一起杀） |
