## 1. 历史记录永远是空的（DataCloneError）

**发生时间**：2026-11-18（W3D3，IndexedDB 落库当天）

### 现象

分析完跳结果页，一切正常：分数、维度条、关键词全都在。
但点「历史记录」，永远是「还没有分析记录」。

控制台一行黄色警告：

```
[analysis] 本地保存失败，本次结果只在内存里
DataCloneError: Failed to execute 'put' on 'IDBObjectStore':
#<Object> could not be cloned.
```

### 原因

存进 IndexedDB 的对象里，`result` 是从 `useScore` 的 `ref` 里取出来的 **Proxy（代理对象）**。
IndexedDB 写盘前要做「结构化克隆」（structured clone，把对象拆成二进制），
它只认普通对象和数组，**碰到 Proxy 直接抛错**。

```js
const result = ref({ score: 72 })
result.value          // 代理对象，不是普通对象
store.put(result.value)   // ← 报错在这
```

为什么页面上看不出来：`saveScore` 里写库失败被 `catch` 住了，只 `console.warn` 就继续跳转。
而结果页的 `restore()` **先看内存里的 `current`**，内存里明明有，所以压根没读库 ——
一个被吞掉的错误，掩盖了一个 100% 必现的 bug。

### 修法

写库前统一剥成纯数据（`src/composables/useLocalDB.ts` 的 `toPlain`）：

```ts
function toPlain<T>(value: T): T {
  return JSON.parse(JSON.stringify(value)) as T
}

export async function putAnalysis(item: SavedAnalysis): Promise<void> {
  await withStore('readwrite', (store) => store.put(toPlain(item)))
}
```

放在 `putAnalysis` 这一层而不是每个调用方各自处理：调用方经常随手传页面里的响应式对象，
指望每个人记得转换，早晚会漏。

为什么不用 Vue 的 `toRaw`：它只剥最外面一层，`result.dimensions` 这种嵌套里还可能是代理。
JSON 一趟到底，而且「能进 IndexedDB 的数据」本来就该是 JSON 那几种形状。

### 测试怎么写才有用

新用例传一个 `reactive()` 包过的对象。关键动作：**把修复临时撤掉跑一遍**，
确认它报出和线上一模一样的 `DataCloneError`，再放回去变绿。
只写测试不验证「它能不能失败」，等于写了条永远绿的假测试。

### 面试口述版（30 秒）

> 我用 IndexedDB 存分析记录，结果页一直正常，但历史页永远是空的。
> 看控制台发现 `DataCloneError` —— 我把 Vue 的响应式对象直接 `put` 进去了，
> 响应式对象是 Proxy，而 IndexedDB 的结构化克隆不支持 Proxy。
> 修法是写库前用 `JSON.parse(JSON.stringify())` 深拷贝成纯数据。
>
> **更值得说的是这个 bug 被我自己的 `catch` 吞了**：写库失败只打了警告、没中断流程，
> 所以界面看起来一切正常，只是历史永远是空的。后来我的原则是：
> 静默失败必须在界面上留下痕迹，否则就是给自己埋雷。

### 追问预案

- **「`toRaw` 和 JSON 拷贝有什么区别？」**
  `toRaw` 只剥一层，嵌套对象、数组元素里还是代理；JSON 深到底。
  代价是 JSON 会丢掉函数、`undefined`、`Date` 会变成字符串 —— 但这几样本就不该往库里存。
- **「为什么不在 `saveScore` 里就处理好？」**
  那样每个写库入口都得记得写一次。放到最底层（`putAnalysis`）是「一处收口」，
  以后新增调用方不会漏。
- **「这种错为什么测试没抓到？」**
  因为之前的测试传的都是字面量普通对象。是测试数据的真实性不够，不是测试写得少。
  补的用例刻意用 `reactive()` 造真实输入。

### 还能顺带讲的两点

- **内存和存储两份数据，谁先被读**：`restore()` 先看内存再看库（快），
  所以「没写进库」这件事被内存挡住了。缓存能加速，也会掩盖写入失败 —— 值得主动提。
- **结构化克隆和 JSON 不是一回事**：前者支持 `Date`、`Map`、循环引用，后者不支持；
  但前者不支持 Proxy。选哪个取决于数据从哪来。

## 2. 删除为什么要按两下（更新策略的取舍）

**发生时间**：2026-11-18（W3D3，历史页删除功能）

### 做法

历史列表每条记录旁有「删除」。点第一下：按钮变红、文案变「确认删除」，**数据不动**；
点第二下才真的删。`confirmId` 这个 ref 记住「哪一行在等确认」，点别的行会自动把上一个恢复。

```ts
async function handleDelete(item: SavedAnalysis) {
  // 第一下：只标记，不动数据
  if (confirmId.value !== item.id) {
    confirmId.value = item.id
    delError.value = ''
    return
  }
  // 第二下：写库，成功了才从列表里剔掉
  const ok = await analysis.remove(item.id)
  if (!ok) {
    delError.value = '删除失败，可能是浏览器不让写本地数据'
    confirmId.value = null
    return
  }
  list.value = list.value.filter((x) => x.id !== item.id)
  confirmId.value = null
}
```

### 两个决定值得讲

**为什么不用 `window.confirm` 弹窗**
弹窗在点完的瞬间弹出来，手指还在「确定」的位置上，很容易顺手点掉。
按钮自己变红变字，第二下的代价是可见的、需要移动手指的，比弹窗更难误触。

**为什么删除不做乐观更新**
同一个页面里「标记已投递」是乐观更新：先改界面，写库失败了再翻回去 —— 因为它错了可以再点一次。
删除错了**撤不回来**，所以顺序反过来：先等写库成功（`remove` 返回 `true`），才改界面。

一句话原则：**能撤销的操作可以乐观，不能撤销的必须悲观。**

### 面试口述版（30 秒）

> 删除我做了两道确认，但不是弹窗 —— 弹窗刚点完就弹，用户容易顺手点掉确定；
> 改成按钮自己在「删除 / 确认删除」之间切换。
> 另外删除和旁边的「标记已投递」更新策略不一样：点赞类的可以先改界面再写库，
> 删除必须写完再改界面，因为删错撤不回来。判断标准就是这条操作能不能撤销。

### 追问预案

- **「两下确认会不会还是误删？」**
  会，但代价低：删一条记录不影响其他数据，而且按钮状态是局部的，不会误触到别的行。
  真要更保险可以加「撤销」提示条（删完 5 秒内可恢复），那是下一步的优化。
- **「`filter` 和 `splice` 有什么区别，为什么用 `filter`？」**
  `splice` 在原地改数组，`filter` 返回新数组。新数组一定会触发 Vue 的更新，
  不用去想「这个变更 Vue 察觉到没有」。

## 3. 清空数据后，占用空间反而变大了

### 现象

设置页点「清空本地数据」，条数确实从 5 变 0，但旁边那行「本站点占用」不降反升，
看着像没清干净。刷新几次，这个数字每次都不一样。

### 原因

三条叠在一起，只有第一条是 bug：

1. **我只改了条数，没重读占用。** 清空后写了 `count.value = 0`，但 `usage` 还是进页面时读的旧值。
   离开页面再回来会重跑 `onMounted`，这时才重新读 —— 于是数字「变了」，看着像清空导致的。
2. **`estimate()` 的 `usage` 不是账目，是估计值。** 规范写明这个数字会被取整和填充
   （rounded and padded），目的是防止网站用精确字节数反推磁盘容量。两次读取之间有几十 KB 的抖动很正常。
3. **删除是逻辑删除，空间不会立刻还。** 浏览器内部要做压缩（compaction），异步进行，
   所以删完马上读，数值可能一点没动。

一条记录才十几 KB，1 和 2 的噪声比真实变化还大。这时候把数字显示到 KB，等于展示噪声。

### 修法

- 抽出 `refreshStats()`，`onMounted` 和清空后各调一次；清空后不硬写 `count = 0`，
  改成重新读库 —— 读出来是 0 才算真清掉了。
- 显示改成粗档：小于 1 MB 就写「不到 1 MB」，大于才给一位小数。
  宁可少给信息，也不给一个会跳的数字。
- 想看真实值去 DevTools → Application → Storage，那里是实际占用，
  比 `estimate()` 可信得多。

### 面试口述版（30 秒）

> 我在设置页显示「占用了多少空间」，用的是 `navigator.storage.estimate()`。
> 测的时候发现清空数据后数字不降反升。查了下，这个值按规范是取整并填充过的，
> 防止网站反推磁盘容量；加上浏览器删数据后要异步压缩，空间不会立刻还回来。
> 我一条记录才十几 KB，噪声比变化还大，所以不显示到 KB 了，改成「不到 1 MB」这一档。
> 结论是这种 API 只能当参考，不能当账本。

### 追问预案

- **「那你怎么确定数据真删了？」**
  不以空间数字为准，以「重新读一遍列表拿到 0 条」为准。数据的真相在库里，不在统计接口里。
- **「为什么不用 `JSON.stringify(data).length` 自己算大小？」**
  能算，但算出来的是字符串长度不是磁盘占用：IndexedDB 还有索引和元数据开销，
  实际会大 10%~20%。自己算只是「更稳定的假数字」，不如直接给粗档。
- **「`localStorage` 和 `IndexedDB` 哪个更容易超限？」**
  `localStorage` 一般 5MB 左右且同步写入，超了抛 `QuotaExceededError`；
  `IndexedDB` 配额是磁盘的百分比（Chrome 约 60%），大得多，而且异步不卡主线程。

## 4. 截图看着坏了，其实是尺子坏了

### 现象

W3 收尾做 375px（iPhone SE 宽度）走查。用无头浏览器截了三张图，两张不对劲：

- 工作台右侧内容被切掉，看起来有横向滚动条
- `/about` 页除导航和页脚外，正文一片空白

按当时的判断，这该是两个真 bug，要记进 W4 的移动端清单。

### 原因

两个都是**验收工具**造成的假象，代码没问题：

**① 虚拟时间把定时器踩爆了。**
无头截图用了 `--virtual-time-budget`（让浏览器快速跑完等待时间，省得真等），
它会把 `setTimeout` 瞬间推进，但 IndexedDB 的异步回调不跟着走。
于是页面永远停在「加载中」的骨架条上，看起来就像卡死或空白。

**② 截图不等于视口。**
`--window-size=375` 只影响渲染窗口，最后裁出来的图会被再切一次，
右侧内容就成了「被切掉」。

### 修法

不再用截图判断布局，改成**直接问页面要数值**：

- 用 `--remote-debugging-port` 开远程调试，走浏览器调试协议（CDP）
- `Emulation.setDeviceMetricsOverride` 把视口真的设成 375
- 等 3 秒**真实时间**（不用虚拟时间），再读：
  - `document.documentElement.scrollWidth` 和 `clientWidth` 是否相等
  - 遍历所有元素，看谁的 `getBoundingClientRect().right` 超出视口
  - 空态页面的 `innerText` 里有没有该出现的那句话

实测五个路由（`/`、`/about`、`/history`、`/questions/abc`、`/result/abc123`）
全部 `scrollWidth == 视口宽`、零超宽元素、空态文案全部命中。两个「bug」不存在。

### 面试口述版（30 秒）

> 移动端走查我用无头浏览器截图，截出来两张图明显坏了：一张右边被切，一张正文空白。
> 我差点当成两个 bug 去改，但先停了一下——**先确认尺子准不准，再判断东西坏没坏**。
> 查下来两个都是工具的问题：一是无头模式的虚拟时间会把定时器瞬间跑完，
> 但 IndexedDB 的异步回调跟不上，页面永远停在加载态，看起来就像空白；
> 二是截图的宽度不等于页面视口，会再裁一次。
> 后来我改成用浏览器调试协议，真实时间下把视口设成 375，直接读 `scrollWidth` 和视口宽度对比，
> 再遍历元素看谁越界。五个页面全部相等，零越界。**结论是截图验不了布局，只有数值能验。**

### 追问预案

- **「那你怎么保证这个测量本身是对的？」**
  反向验证：故意给页面加个 `width: 500px` 的块，同一套脚本必须报出越界。报不出来就说明脚本失效。
- **「真机上和模拟的有差别吗？」**
  有。模拟只改视口，不改触摸、不改 `100vh` 的键盘弹出、不改字体渲染。
  所以模拟只能筛掉明显的布局错，最终还得用真手机点一遍。
- **「为什么不用现成的 E2E 工具（Playwright 之类）？」**
  这个项目就一个页面几个路由，引 Playwright 要装浏览器二进制，包体积和 CI 时间都不划算。
  但真要长期维护，「每次发版自动跑视觉回归」是值得的，我现在是手工 + 一次性脚本。

## 5. 返回 200，但打开的不是我的站

### 现象

W4 部署日。项目名 `offer-lens`，我以为线上就该是 `offer-lens.vercel.app`。
部署完 `curl` 一测：**200**。松一口气，接着测接口——`/api/chat` 返回 **404**，
`/result/abc` 也 **404**，页面 HTML 里还找不到构建产物 `assets/index-*.js`。

按当时的判断，这说明三件事同时坏了：函数没部署、`vercel.json` 的回落规则没生效、静态资源没上传。
差点去改 `vercel.json` 和 `api/` 目录结构。

### 原因

**那个域名根本不是我的。** `vercel.app` 子域名先到先得，`offer-lens` 这个名字早被别人占了，
我的项目实际域名是 `offer-lens-lemon.vercel.app`（Vercel 会自动加后缀）。

所以刚才那一串「坏掉」全是假象：我访问的是**别人部署的同名项目**，
它当然没有我的 `/api/chat`，也没有我的路由和资源指纹。

**HTTP 200 只能说明「这台服务器活着」，不能说明「这是你的服务器」。**

真正的线上问题只有一个：环境变量没配，`/api/chat` 返回 500 + `{"error":"missing_api_key"}`。

### 修法

**先证明「打开的是自己那份」，再谈功能对不对。** 三个指纹，任选其一即可：

1. `<title>` 是不是自己的（当时一看是 `Offer Lens`，我的是 `OfferLens · 简历 × JD 智能匹配`，其实第一眼就能发现）
2. HTML 里引的 JS 文件名，和本地 `dist/assets/` 里的 hash 对不对得上
3. 直接查接口：`GET /v9/projects/{projectId}/domains`，拿项目真实绑定的域名

修完再走正常链路：用 Vercel REST API 写入环境变量（`POST /v10/projects/{id}/env`），
带 `deploymentId` 重新部署（`POST /v13/deployments`），轮询 `readyState` 到 `READY`，
最后三连验收：首页 200 且标题对、`/result/abc` 200（回落生效）、`POST /api/chat` 200 拿到真实回复。

### 面试口述版（30 秒）

> 部署完我 curl 了一下，返回 200，本来准备收工。但顺手测接口发现 `/api/chat` 是 404，
> 路由也是 404，差点去改配置。停了一下先问自己：**我打开的这个 200，确定是我的服务吗？**
> 一查，`vercel.app` 的子域名是先到先得的，`offer-lens` 已经被别人占了，
> 我实际域名带后缀 `-lemon`。刚才那串 404 全是在测别人的站。
> 后来我给自己定了个规矩：**验收第一步不是看功能，是证明「打开的是自己那份」**——
> 对比标题、对比静态资源的 hash、或者直接查项目绑定的域名接口。
> 三个指纹对上之后，才发现真正的问题只有一个：线上没配环境变量，接口 500。

### 追问预案

- **「那你怎么保证新部署真的生效了，而不是看到旧版本？」**
  看构建产物的文件名 hash 和本地 `npm run build` 的输出是否一致；Vercel 每次构建会换 hash。
  再确认一次部署的 `readyState` 是 `READY`，以及部署时间晚于最后一次提交。
- **「为什么会出现同名项目？」**
  `vercel.app` 是公共域名，项目名在全局范围内先到先得。换个唯一一点的名字，或者绑自定义域名就没这问题。
- **「这件事和『防御性编程』有关系吗？」**
  关系在于**不要相信间接信号**。200、部署成功、日志没报错，都是间接信号；
  能直接证明的只有「我拿到的内容里有我的指纹」。
